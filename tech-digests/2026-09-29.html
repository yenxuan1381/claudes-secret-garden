Tech Discoveries

Six things people are actually running or arguing about right now — a menu-bar gateway that lets any coding agent run on any model, an 8B "pick the action" model claiming Jev-level accuracy at a fraction of the latency, an approval-gated skill for shipping agent-built apps to production, a code-search CLI meant to cut agent token bills, a treemap for finding what ate your disk, and a browser fishing game with a custom WebGPU ocean.

FILTER: small teams & solo builds over big-co announcements · working code over hype

01

magpie

What it is

A small MIT-licensed desktop/terminal app that runs a local gateway on 127.0.0.1 and translates between OpenAI, Anthropic, and Gemini APIs, so any of 25+ coding agents (Claude Code, Codex, Gemini CLI, Cursor, Goose…) can run on any model — Codex on DeepSeek, Claude Code on Kimi — picked from a menu bar. Agents never hold vendor keys; it edits their config files surgically and can load-balance across subscriptions.

Why people care

Every coding agent is locked to its own vendor's models by default; swapping a cheaper or open-weight model in used to mean hand-editing configs and writing an API shim per tool. It jumped past 1,700 stars in a day.

For you

Relevant if your team pays for several agent subscriptions: one place to route work to the cheapest adequate model and keep keys out of each tool. The key-holding gateway is also a single point to audit — but it's one more piece of local software sitting on your credentials, so review it before wiring in production keys.

PromisingSolves a real, daily annoyance with a small, well-scoped binary and clear licensing, but days old and the trust surface (it brokers your API keys) needs scrutiny.
github.com/yetone/magpie
02

CLM (Contrastive Language Models)

What it is

An 8B-parameter open model that picks actions by comparing an embedding of the current situation against embeddings of candidate actions, instead of generating text token by token. It claims performance on par with Vercel's Jev decision model across computer-use, gaming and tool-calling tasks at up to 9× lower latency, plus top scores as a best-of-N verifier on Terminal-Bench 2.1 (87.6%) and DeepSWE (81.6%).

Why people care

Agents spend most of their time and money on ranking or verifying options, which LLMs do slowly. Cached embeddings make repeated states ~2.8× faster still, and it shot to the top of GitHub trending with 2,300+ stars.

For you

Classification-shaped work — routing, triage, fraud or compliance flags — is where this pattern could cut cost and latency. The benchmark numbers are self-reported and it needs a separate Qwen3-8B embedding server and truncates states over 2,048 tokens, so treat it as something to benchmark on your own data, not adopt.

PromisingInteresting architecture with big claimed speedups, but self-reported benchmarks and real setup caveats; no independent replication yet.
github.com/Contrastive-LM/CLM
03

golive-skill

What it is

An open-source agent skill plus a zero-dependency Node CLI that takes an app your AI coding agent built and walks it to production: detect what services it needs, plan, get your explicit approval, apply on your own accounts, then verify. Live-tested paths include Vercel/Netlify hosting, Supabase/Neon databases, Porkbun/GoDaddy DNS, Resend email and Stripe test mode.

Why people care

Getting an AI-generated app live is still tedious account-by-account setup — hosting, database, domain, email, payments. This turns it into a gated checklist where DNS writes, production deploys and deletions each need an extra confirm flag.

For you

Mostly a signal for now: it's the 'last mile' between vibe-coded internal tools and something real, and the approval-gated design is the right pattern for anything touching payments. It's v0.1.0-alpha, some features are only mock-tested, and it never auto-rolls-back — don't point it at anything important yet.

ToySensible design and honest about being early alpha with parts unvalidated live; too rough to rely on.
github.com/mikehasa/golive-skill
04

jevgrep

What it is

A CLI for coding agents that finds code by natural-language question (e.g. 'How are database connections pooled?') and returns relevant files, line-numbered excerpts and declaration locations, using Vercel's Jev relevance-judging model to explore the repo hierarchy instead of grepping for symbols.

Why people care

Agents burn a lot of tokens wandering a codebase before they find the right file. The author measured about 30% lower agent cost on ten Python SWE-bench tasks ($7.62 → $5.44) with the same 8/10 solved.

For you

Only matters if your engineers run coding agents on large repos, where search cost is real. The evidence is thin — one run on ten tuned tasks — and the author says credential filtering isn't guaranteed, so keep it off sensitive codebases until you've checked what it sends out.

ToyUseful idea with honest caveats, but the cost claim rests on a single ten-task run.
github.com/dzhng/jevgrep
05

disktree

What it is

A Rust + GPUI treemap app for Linux, macOS and Windows that draws your disk as an interactive mosaic coloured by kind of data (code, agent scratch, toolchains, caches, git, media), with hatching on space it judges reclaimable. You mark items, review them, delete or trash, and it rescans to show what you actually recovered.

Why people care

Modern dev machines fill up with caches, toolchains and AI-agent scratch directories nobody remembers creating; it makes 'what ate my disk' answerable at a glance with safeguards against deleting system paths. It hit 1,800+ stars in a day.

For you

Mostly just cool and genuinely handy for anyone with a full laptop. No finance or business angle; it does require Vulkan GPU support and, on macOS, Full Disk Access.

ToyA polished single-purpose utility — useful, not industry-changing.
github.com/tobi/disktree
06

Tidewater

What it is

A browser fishing game on a Caribbean island — cast from piers or a boat, sell catches, upgrade gear — built on a custom WebGPU/WGSL engine with FFT ocean simulation, physically-based atmosphere, and spatial audio. Its description says the coastal town was built with Opus 5.5, and it's MIT-licensed with a live demo.

Why people care

It's a striking public example of how far a small team plus an AI coding model can now go on hard real-time graphics work that used to need a specialist engine team, and it runs with no install.

For you

Mostly just cool. It's a data point on AI-assisted development capability on a hard technical problem, not a business. Needs a recent WebGPU browser and a capable GPU, and first load compiles hundreds of shaders (a minute or more).

ToyImpressive technical demo with nothing to monetise or depend on.
github.com/dgreenheck/tidewater
